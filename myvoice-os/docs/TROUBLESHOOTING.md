## 1. Hardware & Audio Issues

### 1.1. Loud Buzzing, Whine, or Clicking from Speaker
- Cause: Insufficient power decoupling or ground loops between the amplifier and the ESP32 Wi-Fi radio bursts.
- Fix:
  1. Solder a 100uF to 220uF electrolytic capacitor directly across the `VIN` and `GND` pins of the MAX98357A amplifier.
  2. Power the MAX98357A from the 5V USB rail rather than the 3.3V pin of the ESP32.
  3. Ensure both the microphone, amplifier, and ESP32 share a solid common ground plane.

### 1.2. Microphone Records Silence or Zero-Volume Audio
- Cause: Incorrect `L/R` channel pin configuration or inverted `SCK` / `WS` clock lines.
- Fix:
  1. Ensure the `L/R` pin of the INMP441 is firmly tied to `GND` (Left channel). If left floating, the microphone output is high-impedance and undefined.
  2. Verify GPIO pins in firmware:
     - `SD`: GPIO 32
     - `WS`: GPIO 25
     - `SCK`: GPIO 33
  3. Check the rubber acoustic gasket on the microphone sound port to prevent acoustic leakage.

### 1.3. SSD1306 OLED Screen Dark or Scrambled
- Cause: Incorrect I2C address or reversed clock/data lines.
- Fix:
  1. Standard SSD1306 modules use I2C address `0x3C`. Some modules use `0x3D` (check jumper resistor on back of display).
  2. Verify wiring:
     - `SCL`: GPIO 22
     - `SDA`: GPIO 21
  3. Ensure supply voltage is 3.3V. Applying 5V directly to some display controllers may trigger thermal shutdown.

### 1.4. ESP32 Brownout Reset (`rst:0x10 (RTCWDT_RTC_RESET)`)
- Cause: USB power supply cannot deliver the transient 450 mA current peaks demanded when Wi-Fi transmits simultaneously with speaker playback.
- Fix:
  1. Power the ESP32 using a dedicated 5V / 2.0A USB power supply.
  2. Avoid powering through unpowered USB hubs or long, thin USB cables.

## 2. Network & Connectivity Issues

### 2.1. Device Cannot Connect to Wi-Fi / Stuck in AP Mode
- Symptom: ESP32 broadcasts `MyVoice-Setup-XXXX` and never pairs.
- Fix:
  1. Connect a phone or laptop to `MyVoice-Setup-XXXX` (password: `myvoice123`).
  2. In the captive portal browser window, select your 2.4 GHz Wi-Fi SSID and enter your password. (ESP32 does not support 5 GHz Wi-Fi).
  3. If Wi-Fi credentials change, trigger remote clear Wi-Fi from the dashboard or hold the button for 10 seconds to reset.

### 2.2. WebSocket Disconnects with Code 4001 or 4003
- Cause: Token authentication failure or device revoked.
- Code 4001 (Unauthorized): Device token mismatch. Re-pair device in dashboard.
- Code 4003 (Revoked): The device has been marked revoked in the database.

## 3. Server & Database Issues

### 3.1. Database Locking (`sqlite3.OperationalError: database is locked`)
- Cause: Long-running synchronous transactions competing with concurrent async WebSocket writers.
- Fix:
  1. SQLite is configured with WAL (Write-Ahead Logging) mode and 15-second busy timeouts.
  2. In production, ensure storage volume is local SSD and not a network NFS drive.

### 3.2. Open-Meteo or Brave Search API Timeouts
- Fix:
  1. Tools are shielded with a 5.0 second timeout (`ToolRegistry.execute_tool`).
  2. If the external weather API is temporarily down, `WeatherTool` automatically serves a graceful fallback report.

## 4. OTA Firmware Update Troubleshooting

### 4.1. OTA Upload Rejection: "Invalid binary: magic byte 0xE9"
- Cause: The uploaded file is not a raw compiled ESP32 firmware binary (for example, uploading an ELF or HEX file instead of `.bin`).
- Fix: Ensure you upload `firmware.bin` generated by PlatformIO (`.pio/build/esp32dev/firmware.bin`).

### 4.2. Flash Size Exceeded
- Cause: Firmware binary exceeds partition capacity.
- Fix: Current firmware is 1.18 MB. If adding extra libraries, configure a custom partition table such as `min_spiffs` (1.8 MB app partitions on 4 MB flash).
