# Falcon AI - Web Firmware Flasher for regular ESP32

This ZIP includes a complete **static website for installing compiled ESP32 firmware via USB from your own website**, a safe firmware publisher, automated tests, and the **previous Falcon AI source overlay** for your cloned `xiaozhi-esp32` repository.

> **There is NO compiled firmware in this ZIP.** The previous ZIP contained source code, not a runnable `.bin`. The website intentionally disables flashing until you publish your **real, built** ESP32 firmware. This prevents mistakenly flashing an empty or dummy image.

## Step 1: Build firmware on your computer (once per version)

Use ESP-IDF matching the current `xiaozhi-esp32` repository and your **actual flash size**. First apply your personal board overlay (if you have not already):

```bash
cd FalconAI_WebFlasher/source_overlay
python3 apply_falcon.py --repo /path/to/xiaozhi-esp32 \
  --profile myvoice --flash-size 4MB \
  --ota-url http://YOUR-LAN-SERVER-IP:8002/xiaozhi/ota/
```

Then build in your existing cloned firmware repo:

```bash
cd /path/to/xiaozhi-esp32
python scripts/build.py falcon-ai-esp32 --language en-US --wake-word disabled
```

Your repo may provide a `build/merged-binary.bin`. **Only use it if generated by the real successful board build.** A merged image needs all bootloader, partition and application pieces. If the build only produced multiple `.bin` files and `build/flasher_args.json`, you can let our publisher invoke `esptool` to merge them.

## Step 2: Publish the firmware into your website

Run from any directory (adjust paths):

**Option A: Your repository created `merged-binary.bin`**

```bash
python3 FalconAI_WebFlasher/tools/publish_firmware.py \
  --merged /path/to/xiaozhi-esp32/build/merged-binary.bin \
  --version 0.1.0 --flash-size 4MB --profile myvoice
```

**Option B: Your ESP-IDF build has `flasher_args.json`**

Install `esptool` first: `python3 -m pip install esptool`.

```bash
python3 FalconAI_WebFlasher/tools/publish_firmware.py \
  --idf-build /path/to/xiaozhi-esp32/build \
  --version 0.1.0 --flash-size 4MB --profile myvoice
```

This **generates**:

```
site/firmware/
  manifest.json
  release.json
  falcon-ai-esp32.bin
```

The manifest uses the **merged image at flash offset 0**, as recommended by ESP Web Tools. The publisher checks the ESP32 bootloader header and flash size, calculates SHA-256, and avoids publishing a source ZIP or application-only image.

**Very important:** `--profile` is **release metadata**, not an automatic firmware patch. Choose the profile actually used when building the firmware. Confirm your board's flash size in hardware; do not assume 4MB if it differs.

## Step 3: Preview or deploy your website

### Test locally

From the `site` directory:

```bash
cd FalconAI_WebFlasher/site
python3 -m http.server 8008
```

Open **http://localhost:8008** in desktop Google Chrome or Microsoft Edge. `localhost` is a valid secure context for Web Serial. You cannot double-click `index.html` and use `file://`.

### On your domain

Upload **everything inside `site/`**, including `firmware/`, to your website's `/flash/` directory. Then open:

`https://YOUR-DOMAIN.com/flash/`

- Netlify/Vercel: deploy `site/` as a standalone static project and link to it from your main website.
- GitHub Pages: serve from repository root or `docs/`, or copy the `site/` content under your page's `/flash` path.
- Existing React/Vite/Next project: put the files under your site's static `public/flash/` directory; keep manifest and firmware same-origin.
- WordPress: host the `site/` folder at a distinct `/flash/` path (not as a WordPress post body).

**HTTPS is REQUIRED** for browser flashing outside localhost. Chrome or Edge on a computer is recommended. Ensure the website and firmware are hosted under the same origin, otherwise CORS headers will be necessary.

## Website integration snippet (instead of embedding the whole page)

After running the publisher, your website can also embed this directly:

```html
<script type="module" src="https://unpkg.com/esp-web-tools@10/dist/web/install-button.js?module"></script>
<esp-web-install-button manifest="/flash/firmware/manifest.json">
  <button slot="activate">Install Falcon AI Firmware</button>
  <span slot="unsupported">Use Chrome/Edge on a compatible desktop.</span>
</esp-web-install-button>
```

**Only show the install button after publishing a valid real firmware image.** The provided full website already performs a manifest/asset availability check. The snippet above doesn't check this automatically.

## Safety and limitations

- This website **does not compile firmware**; server-side or local ESP-IDF compilation happens before publishing.
- Chip-family detection cannot verify your specific GPIO wiring, OLED model, or flash capacity; double-check your actual hardware first.
- Flashing may wipe Wi-Fi credentials, pairing tokens and existing data; back up before installation.
- Do not publish ESP32 firmware containing embedded API keys, secrets or private Wi-Fi credentials.
- ESP Web Tools flashing is a USB operation on the visitor's connected machine; it cannot flash a remote ESP32 over the internet. After initial USB provisioning, separate OTA support can update devices remotely if implemented.
- `improv: false`: the page does not promise Improv serial Wi-Fi provisioning. Use the firmware's own Wi-Fi setup method.
- The self-hosted XiaoZhi server and device pairing must be operating separately; installing firmware does not itself deploy a server.
- The source overlay is from your previous Falcon AI package. It is **not** a precompiled firmware or a guaranteed match for an arbitrarily updated upstream checkout.
- The installer UI and generator are created here, but real physical ESP32 flashing remains **untested** without your compiled `.bin` and board.
